## 2026-11-09: the first map in Pith, its cost on screen and the daily check

This closes the list above of what wasn't verified yet. Each run was Pith's own build, mapping this Mac's whole disk with Disk open, without Full Disk Access.

- **The first map without Full Disk Access:** macOS asked about the folders it protects one question at a time: Downloads, Documents, Desktop, other apps' data, iCloud Drive's files and Reminders. It refused Photos without asking. Opening a folder behind an unanswered question waits until the person answers, however long that takes. Four defects followed, each now fixed:
  - Every walk asked about "files on a network volume". Opening `/System/Volumes/Data/home`, the automount every Mac has, counts as one. The map now finds volumes in the mount table and never opens one outside the mapped disk's container. The minute's check of volume space read every volume too, on the scanner's main thread, and now reads only the disk's own.
  - All 12 listing threads waited on the questions within a second, and the map waited with them, at about a quarter of the disk, for the 10 minutes until someone answered. A listing still opening after half a second now gets a thread in its place, and the folders likely behind the same question wait behind three probes, so the rest of the disk goes on. With only folders behind questions left, the map is done, Disk says "macOS is asking whether Pith may read N folders", and each joins the map when answered. A daily check ends the same way.
  - The folders behind one question needn't share a parent. Every app container's Data folder is behind one question, so holding back only a stuck folder's siblings still let 64 threads get caught. Folders of the stuck folder's name beside its parent now wait too, and the threads allowed went from 64 to 120, since each place macOS asks about can catch every free thread before its gate closes.
  - A listing that waited for an answer counted the wait as its cost, and the cooldown that follows held changes inside the folder for two hours. "Catching up" grew from 3,957 folders to 5,060 in 45 s. The wait no longer counts.
- **With the fixes:** no network question. A first map, made before folders of one name waited together, was done 36 s after Disk opened, with questions still unanswered. Reopened on a map saved while questions waited, Pith showed it at 429 GB with one folder waiting and filled in to 861 GB within 66 s as the questions were answered, matching the walk from the terminal. The folders waiting to be listed again went from 724 to the usual few within two minutes. At most 85 threads were held.
- **The whole disk's map on screen:** Disk refreshes the map every two seconds while it changes. Pith itself took 29.9% of a core over five minutes, and 225 mW over 90 s against 10.9 mW with Disk closed. The cost was splitting the scanner's output into lines: each 64 KB read of the 2.8 MB map was searched again from the line's start.
